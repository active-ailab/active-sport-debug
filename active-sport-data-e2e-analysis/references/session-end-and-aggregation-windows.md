# 运动结束与聚合窗口分析

## 四条链路分别对照

不要将设备端所有模块或APP所有消费者合并成一个时间窗口。使用下表，只填写日志或代码能够证明的内容：

| 事件/字段 | 固件实时算法 | 固件运动记录 | APP运动记录 | APP算法 |
|---|---|---|---|---|
| 启动 | BEGIN实际接收时刻 | 保存的起点 | 解析起点 | session起点和窗口起点 |
| 暂停 | 是否处理PAUSE | 时长/采样是否冻结 | 是否保留暂停区间 | 是否消费暂停区间 |
| 恢复 | 状态及累计量如何继续 | 如何累计暂停时长 | 是否保留恢复时刻 | 如何映射墙钟分钟 |
| 确认保存 | 是否已有业务结束边界 | 是否等待尾包 | 同步后可见哪些字段 | 是否使用保存时刻 |
| 正式结束 | END接收时刻及生效边界 | STOP时刻、最终保存时长 | 终点是协议原值还是派生值 | 实际结束索引及开闭区间 |
| 同步/计算 | 现场输出 | 写入/上传时刻 | 解析/落库时刻 | 离线调用与输出时刻 |

APP通常事后处理记录，不应把APP解析得到的起点描述成现场收到了START。缺少暂停字段时写“未提供/未观察到”，不能默认暂停时刻等于记录终点。

## 记录终点可能是计算值

分别验证：

```text
record_end = record_start + saved_duration
```

- 确认使用total还是net、秒还是毫秒，并检查整数截断。
- 检查未结束的暂停是否被扣除；不能根据字段名total推断一定包含等待保存的时间。
- 本次暂停后未恢复时，派生终点可能接近暂停处。
- 中途多次暂停时，起点加净时长通常不等于实际墙钟结束时刻。
- 记录终点、命令到达时间都可能自洽；是否符合业务要求，需要对照双方约定。

暂停间隔的具体扣除规则见 [总用时、运动用时与最后暂停](time-semantics-and-invariants.md#总用时运动用时与最后暂停)。报告应分别列出已恢复暂停时长、最后未恢复暂停时长、total、net及APP采用的字段，避免把所有暂停统一从total扣除。

## 分钟数据的时间标签

报告优先使用“计入运动的分钟数据条数”。首次出现“桶”时解释：它是一分钟范围的汇总输入，条数不表示完整运动分钟数、卡路里或算法分数。

先确认某条日志标记的是区间起点还是结算终点。例如若约定成立：

```text
设备 min_end = 10:08，数据对应 [10:07,10:08)
APP label   = 10:07，数据对应 [10:07,10:08)
```

两者应按同一数据区间对齐，不能直接比较相同标签。数组索引由数组原点、步长和标签语义共同确定，不固定使用加一或减一。

## 开闭区间与取整

分别记录真实起止、传入算法的起止和循环条件。若业务约定纳入与运动区间有交集的分钟，且循环为半开区间 `[start_idx,end_idx)`，可验证：

```text
window_start = floor(actual_start / 60) * 60
window_end   = ceil(actual_end / 60) * 60
record_count = (window_end - window_start) / 60
```

公式使用秒；毫秒输入需先统一单位。恰好到整分钟的结束值不会额外增加一分钟。不要用“起点向下取整 + 整数运动分钟数”代替实际终点，也不要一律给时长加一。

上述规则取决于业务约定；仅发现两端取整不同，还不足以认定哪端应修改。需说明采用完整分钟、相交分钟或其他规则。

## 把偏差拆成独立区间

列出共同计入、仅设备计入、仅APP计入的分钟区间。逐区间解释差异来自暂停、结束取整、采样缺失还是消息延迟。

分别计算：

```text
暂停后等待 = 确认保存时刻 - 最后暂停时刻
尾包等待   = final到达时刻 - drain开始时刻
命令派发   = 算法收到END时刻 - STOP派发时刻
```

不要把暂停到算法END的总间隔都写成“保存耗时”。只有取得用户确认或UI操作日志时，才把相应阶段定性为用户等待。

## 逐字段核对与分值归因

1. 固定同一session和算法调用，完整提取分钟数组、窗口和版本。
2. 对齐标签后，比较各字段和缺失项，输出比较条数、差异数量及具体下标。
3. 保留原值；无效值可能有不同编码，若需归一化，应同时报告原始差异和映射依据。
4. 相同输入数组不代表相同运动窗口；范围需单独比较。
5. 同样的窗口也不自动保证相同结果；还需核对算法版本、初始状态及其他输入。
6. 量化某段时间对分数的贡献时，做受控回放。未经回放，不将“多两条分钟数据”写成“必然多两分”。

引用日志行号时保持原文件行定义。对含控制字符的文件，可按原始字节的换行符切分；某些文本读取器的通用换行转换或 `splitlines()` 会改变行号，应与 `rg -n` 回核。

## 修复和回归边界

暂停是可恢复状态。不能在每次暂停时永久结束算法而不考虑恢复后的session身份、累计状态和最终结果。

按算法实际支持的暂停/恢复、有效区间或回溯结算能力设计修复。分别验证：直接结束、暂停后立即保存、长暂停后保存、暂停恢复再结束、多次暂停、结束恰逢整分钟及跨日。每例核对四条链路的事件时刻、保存时长和实际输入范围。

若输入没有专项算法所需的校准或站点数据，先沿实际通用路径分析；其他样本已确认的站点偏移只能作为独立风险，不作为本次分值差异的直接原因。
