# 跨层数据核对清单

## 通用链路

- 生产端字段的类型、单位、有效值和缺省值。
- 大小核/主从设备的路由和编译宏。
- Engine 是否改写时间戳、聚合窗口或缓存数据。
- Service listener 是否过滤、去重、延迟消费或按状态机丢弃。
- cache 保存的是增量、累计值还是原始数组。
- record tag 的长度、版本、尾插兼容、相对时间原点。
- APP parser 是否按新旧长度解析，是否存在字段错位/截断。
- APP 不同消费者是否使用同一个模型：详情页、二次算法、上传、统计可能是独立链路。

## 时间、LAP 与站点

- session start、段 S/E、LAP 构建 T、节点 relative_time 是否已全部标注。
- 自动/手动切换是否使用相同 final 口径。
- 切换延迟是否仅影响通知，还是错误影响数据归属。
- 上一段、当前段、下一段的 start baseline 是否同时更新。
- `lap_index`、站点类型和记录顺序是否一一对应。
- 最后一站退出是否能正常 final 并解除保存等待。

## 距离与配速

- 距离源：GPS、步频估算、跑步机、Stryd 或融合值。
- 瞬时配速、窗口配速、分段平均配速的分母是否匹配。
- 分段距离使用边界累计值之差，不能使用通知时当前值。
- 力量站即使输出距离/配速，也要区分“引擎有值”和“UI 默认展示”。
- 0 距离、断连、暂停和跨站缓存不能产生除零或异常配速。

## 卡路里、心率、功率与体温

- 卡路里总量保持单调；分段值使用边界累计消耗之差。
- 心率平均值按样本数加权，不能平均两个平均值。
- 分段功率/体温需保留旧段 final 和新段 carry；全程最大/最小/平均不因边界修正重复累计。
- Stryd/体温计未连接、断连重连和无有效样本时，明确缺省值与页面行为。
- 3/10/30 秒窗口值通常是实时项，不自动等同于记录落盘字段。

## REP 与计次

- `rep_count` 的增量/累计语义必须由代码或接口确认。
- chunk/segment 只是存储拆包时，不应改变逻辑动作序列。
- `rep_start_ms/end_ms` 的原点必须明确，并检查所有动作落在 `[S,E]`。
- 4 秒聚合包、尾包和重复包不得导致 REP 重复或遗漏。
- HTE 修正值、原始值和 APP 展示值要分别记录。

## 状态与异常矩阵

至少按适用范围检查：

| 场景 | 关注点 |
|---|---|
| 功能宏关/开关关 | 与历史手动流程等价 |
| 自动切换 | 延迟通知、边界修正、UI 切换、尾包 |
| 手动切换 | UPDATE 时序、短时误报、防重入 |
| 暂停后恢复 | 已发通知、排队消息、时钟口径、长暂停 |
| 运动停止 | final station、final master、保存放行、超时 |
| 外设断连 | 缺省值、恢复后窗口、记录字段 |
| 算法无输出/空数组 | 空值兼容、状态机不悬挂 |
| 重复/乱序消息 | 幂等、单调性、站点索引 |
| 旧记录/旧 APP | 协议长度兼容和回退口径 |

## 完成判据

- 每个争议数据项有生产公式、边界、协议字段和消费位置。
- 至少一个真实或可控模拟样本完成数值闭环。
- 异常场景未覆盖时明确列出，不写“完全正常”。
